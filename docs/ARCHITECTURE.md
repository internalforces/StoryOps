# StoryOps 아키텍처

StoryOps는 공개 포트폴리오와 비공개 원고 처리 영역을 분리한 로컬 우선 프로토타입이다. 데모 앱은 합성 데이터만 포함하며 GitHub Pages에서 정적 배포된다.

```mermaid
flowchart LR
    A[원본 원고·설정·이미지] --> B[날짜별 백업 + SHA-256]
    A --> C[가져오기 파이프라인]
    C --> D[회차·상태별 분할]
    C --> E[비공개 매니페스트]
    D --> F[private/ 로컬 전용]
    E --> F
    F --> S[매니페스트 로컬 선택]
    S --> H
    C --> G[원문 없는 공개 집계]
    G --> H[React 관리 화면]
    I[합성 작품·회차·설정] --> H
    H --> J[문장 분할]
    J --> K[한글 토큰·2-gram 검색]
    K --> L[구조화된 충돌 후보]
    L --> M[근거 회차 표시]
    M --> N[승인·오탐 피드백]
    O[충돌/정상 회귀셋] --> P[정확도·재현율·Hit@5·MRR]
    P --> H
    H --> Q[GitHub Actions]
    Q --> R[GitHub Pages 라이브 데모]
```

## 데이터 경계

- `private/`: 백업, 분할 원고, 원본 파일명과 해시를 가진 매니페스트. `.gitignore`로 차단한다.
- `public/data/`: 원문이 없는 가져오기 집계와 공개 가능한 합성 데이터만 둔다.
- `src/data/seed.ts`: 데모 목적의 합성 작품·인물·설정·평가셋이다.
- 로컬 매니페스트 연결: 사용자가 `manifest.private.json`을 직접 선택하며 서버 전송은 없다. 작품·회차·상태만 변환하고 원문, 원본 파일명, 해시, 로컬 경로는 버린다.
- 브라우저 저장소: 공개 데모 또는 변환된 회차 메타데이터와 승인/오탐 판단을 기기 안에 보관한다.

## 핵심 결정

1. **안정 ID와 내용 해시 분리**: 회차가 수정되어도 ID는 유지하고 SHA-256만 바뀐다.
2. **근거 우선 출력**: 충돌 문장, 정본 설정, 근거 회차, 신뢰도, 검수 상태를 한 레코드로 묶는다.
3. **사람이 최종 판정**: 자동 검사는 후보를 만들고 승인·오탐은 사용자가 결정한다.
4. **비용 0인 공개 데모**: 외부 API 키 없이 검색과 규칙 기반 판정을 브라우저에서 수행한다.

## 프로덕션 확장 지점

- 브라우저 저장소를 PostgreSQL + 행 수준 권한으로 교체
- 한글 임베딩 검색과 벡터 색인을 검색 계층에 추가
- LLM 구조화 출력(JSON Schema)을 충돌 판정 어댑터로 추가
- 오탐 피드백을 작품별 평가셋과 검색 재정렬 데이터로 축적
- 워크스페이스·역할·감사 로그·버전 스냅샷 추가
