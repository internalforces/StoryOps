# 평가 설계와 결과

## 목적

연속성 검사가 관련 정본 설정을 찾는지, 직접 충돌과 정상 문장을 구분하는지, 그리고 추가 문맥 없이는 단정하면 안 되는 사례를 얼마나 식별하는지 검증한다. 좋은 점수만 보여주는 데모가 아니라 현재 규칙 엔진의 실패를 재현하고 다음 개선을 비교할 수 있는 기준선을 만드는 것이 목적이다.

## 데이터셋

공개 평가셋은 실제 집필 과정에서 발견한 문제 유형을 바탕으로 만들되, 문장·인물·장소·설정은 모두 공개 데모의 합성 세계관으로 다시 작성했다. 실제 원고 문장은 포함하지 않는다.

| 실패 유형 | 건수 | 검증 질문 |
|---|---:|---|
| 직접 규칙 | 10 | 등록된 충돌 표현과 정상 표현을 구분하는가 |
| 미등록 표현 | 10 | 동의어·비유·우회 표현도 충돌로 찾는가 |
| 정상 변화 | 10 | 설정 변경 전후를 구분해 정상 변화를 보존하는가 |
| 회상 문맥 | 10 | 과거 회상·기록을 현재 사실과 분리하는가 |
| 의도적 거짓말 | 10 | 화자의 발화를 세계관 사실로 단정하지 않는가 |
| 불확실한 기억 | 10 | 엇갈리거나 변조된 기억에 추가 검토를 요구하는가 |
| 별칭 연결 | 10 | 인물·장소·사물의 별칭을 같은 엔티티로 연결하는가 |
| **합계** | **70** | 충돌 21 · 정상 19 · 문맥 필요 30 |

실제 원고와 공개 합성 데이터의 연결은 Git에서 제외된 `private/evaluation/source-cases.private.json`에 실패 유형, 근거 위치, 요약만 보관한다. `npm run evaluate:private`는 이 근거 맵과 원본 위치가 유효한지 내용 노출 없이 확인한다.

## `rule-v1` 기준선

2026-08-09 로컬 브라우저 실행 결과다. 실행 시간은 기기와 브라우저에 따라 달라지므로 고정 성능 수치로 보지 않는다.

| 지표 | 결과 | 의미 |
|---|---:|---|
| 전체 통과 | 14/70 (20%) | 기대한 3단계 결과와 일치한 문장 |
| 충돌 재현율 | 5/21 (24%) | 의도한 충돌 중 규칙이 찾아낸 건수 |
| 충돌 정밀도 | 5/15 (33%) | 충돌로 판정한 비문맥 문장 중 실제 충돌 |
| 문맥 식별 | 0/30 | 회상·거짓말·불확실한 기억을 `문맥 필요`로 출력한 건수 |
| 검색 Hit@5 | 70/70 (100%) | 정답 설정이 검색 상위 5개에 포함된 건수 |
| MRR | 1.00 | 정답 설정의 평균 역순위 |
| API 비용 | $0 | 브라우저 내 결정론적 실행 |

검색은 합성 세계관에서 정답 설정을 안정적으로 찾지만, 판정은 직접 표현 외의 의미와 문맥을 처리하지 못한다. 검색과 판정을 분리해 측정했기 때문에 “검색 성공”을 “충돌 판단 성공”으로 오해하지 않는다.

## 해석과 다음 개선 순서

1. 시간축·화자·기억 신뢰도를 판정 입력에 연결하고 `문맥 필요` 출력을 먼저 구현한다.
2. 별칭 사전을 엔티티 검색 전에 정규화해 같은 인물·장소·도구로 연결한다.
3. 의미 검색 또는 LLM 판정 어댑터를 추가해 미등록 표현의 재현율을 높인다.
4. 같은 70건을 다시 실행해 유형별 변화와 새로운 오탐을 비교한다.

이 기준선은 실제 원고 전체에 대한 일반화 성능을 주장하지 않는다. 70건은 알려진 실패 유형을 반복 가능하게 재현하는 회귀셋이며, 프로덕션 평가는 작품별 블라인드 셋과 사람 간 합의 기준을 추가해야 한다.
