# 실제 문제 해결 사례: 120회 장편 원고 정리

## 문제

장편 원고가 35개 Markdown 문서와 여러 이미지에 흩어져 있었다. 문서 하나에 5~10개 회차가 묶였고 초안·완성본·설정집·로드맵이 파일명에만 의존해 구분됐다. 공개 포트폴리오를 만들려면 실제 원고 유출 없이 구조와 해결 과정을 보여줘야 했다.

## 처리

- 전체 원고와 인물 이미지를 날짜별 압축본으로 백업하고 SHA-256 체크섬을 생성했다.
- 완성본의 `## N화`, 초안의 `# N화 초안` 머리말을 기준으로 회차를 분할했다.
- 작품·회차·상태가 드러나는 안정 ID를 부여했다.
- 원문·원본 파일명·해시는 `private/`에, 집계와 합성 데모 데이터는 공개 영역에 배치했다.
- 중복 ID와 분할 실패를 자동 검사했다.

## 결과

| 항목 | 결과 |
|---|---:|
| 고유 회차 | 120 |
| 초안 버전 | 120 |
| 정본 버전 | 120 |
| 분할된 회차 파일 | 240 |
| 참고 문서 | 5 |
| 인물 이미지 | 6 |
| 중복 ID | 0 |
| 분할 경고 | 0 |
| 공개된 원문 | 0 |

## 배운 점

콘텐츠 자동화 프로젝트에서 검색 기술보다 먼저 해결해야 할 것은 데이터 경계와 근거 추적이다. 회차·상태·가시성·해시가 안정돼야 검색 결과가 어떤 정본에서 왔는지 설명할 수 있고, 작가의 승인과 오탐 판단도 재사용 가능한 데이터가 된다.
